# WorkingPet 插件（VPet 打工宠物）

把旧版 Python 桌宠 WorkingPet 的"打工人"功能移植成 VPet 的代码插件（MOD），不修改 VPet 本体。

## 功能

| 功能 | 说明 |
|---|---|
| 打工面板 | 悬浮在宠物旁边：时钟、日期、今日进度环、已工作/还需时长。按状态变色，可调大小、透明度、颜色，可跟随宠物或自由拖动 |
| 下班流程 | 下班前 3 秒：预备动作 + 气泡倒数 3-2-1（带"今天加班"按钮）；到点：跑到屏幕中央并放大，点"知道啦"后缩小跑回原位并睡觉 |
| 后台采集 | 窗口活动、应用使用时长、屏幕描述，供日报/周报自动取材，可同步到私有 git 仓库 |
| 工作记录 | "记录工作"快速记一条；"工作日历"按日期查看/补录/修改，可导入旧版 `work_log.json` |
| AI 功能 | 豆包：对话（自动识别记录/周报/钉钉/闲聊）、本周周报、今日日报草稿（下班前 10 分钟自动弹出，确认后覆盖当天记录） |
| 提醒 | 周报按设定的星期和时间提醒；一键打开钉钉 |

入口都在宠物工具栏 **自定 → 打工宠物** 子菜单里；MOD 管理页的"MOD设置"打开同一个设置窗口。

## 构建与安装

```powershell
cd VPet.Plugin.WorkingPet
dotnet build -c Debug
```

产物在 `bin\Debug\net8.0-windows\mod\WorkingPet\`。把整个 `WorkingPet` 文件夹复制到 VPet 的 `mod\` 目录下，
在游戏设置 → MOD 管理里选中 WorkingPet，点红色的"启用代码插件"，再重启游戏。更新 DLL 前要先退出游戏。

## 后台采集（默认开启，永久保留）

| 采集项 | 做法 |
|---|---|
| 窗口活动 | 每 30 秒记录前台窗口；窗口切换时记一条；累计各应用的使用时长（人离开电脑超过 5 分钟不计，锁屏不计） |
| 活动摘要 | 每 2 分钟让 AI 把这段时间的窗口标题总结成一句话；娱乐、闲聊或无法判断时留空 |
| 屏幕描述 | 每 15-30 分钟截一次主屏，让视觉模型用一句话描述；**截图只在内存里，不保存**。需要你的接入点背后是支持图片的模型，连续失败 3 次会暂停 6 小时 |

全天采集，不做关键词过滤；日报/周报生成时由 AI 自己剔除娱乐和个人内容。可以在"AI设置"里单独关闭窗口活动或屏幕描述。
日报会用到：手动记录 > 活动摘要 > 屏幕描述 > 应用时长 > 窗口标题；周报在某天没有手动记录时用活动摘要兜底。

## 数据存在哪

**数据目录**（默认 `%AppData%\VPet-WorkingPet\data\`，可在"AI设置"里改成任意文件夹，改后重启游戏生效）：

| 路径 | 内容 |
|---|---|
| `work_log.json` | 工作记录（格式与旧版相同） |
| `samples\yyyy-MM-dd.jsonl` | 窗口切换记录 |
| `activity\yyyy-MM-dd.jsonl` | AI 活动摘要（含依据的窗口标题） |
| `vision\yyyy-MM-dd.jsonl` | 屏幕描述 |
| `apps\yyyy-MM-dd.json` | 当天各应用使用秒数 |

采集数据按天分文件、只追加、永不自动删除。

**本机配置**（`%AppData%\VPet-WorkingPet\`，不在数据目录里，**不会被同步**）：`ai_config.json`（API Key 等）、`debug.log`（排查日志，超过 200KB 自动清空）。

面板和下班流程的设置随 VPet 存档保存。

## 同步到云

两种方式可以同时开，在"AI设置"里勾选；同步间隔共用（默认 6 小时），启动 2 分钟后先同步一次，退出游戏时也会同步一次；菜单里有"立即同步数据"。

### Steam 云（默认开启，需要通过 Steam 启动游戏）

用的是 VPet 自己存档同款的 Steam 云存储接口，文件放在云上的 `WorkingPetCloud/` 下，和游戏存档（`VPetCloud/`）互不干扰。

- 采集数据会无限增长，而 Steam 云有文件个数和总大小的配额，所以按月打成一个 zip（文本压缩后很小），只重传有变化的月份，已过去的月份不会再动。
- 多台电脑：每次先把云上其他电脑传的新内容合并进本地（jsonl 按行去重、按时间排序；工作记录按条去重），再把合并后的结果传上去。云上的文件如果是自己传的就不会重复合并，所以删掉的记录不会"复活"。
- 要求：这台电脑的 Steam 里，VPet 的"属性 → 通用 → 将游戏存档保存在 Steam 云中"是勾选的。配额由游戏开发者设定，插件读不到具体数值；写入失败时会提示。
- 同步状态记在本机 `%AppData%\VPet-WorkingPet\steam_sync.json`。

### git（需要自己建私有仓库）

把数据目录变成**私有** git 仓库的本地副本，再勾选"自动同步到 git"：

```powershell
cd 你的数据目录
git init
git remote add origin https://github.com/你/你的私有仓库.git   # 必须是私有仓库
```

自动 `add → commit → pull --rebase → push`。用的是你机器上已有的 git 和凭据，插件不保存账号密码。
**如果 origin 是公开的 GitHub 仓库，会拒绝推送**，因为数据里是你的活动记录。冲突时会放弃这次合并并提示，不会弄乱仓库。

数据没有写进 VPet 的游戏存档本身：采集数据会无限增长，塞进存档会拖慢每次保存/读取，还可能影响存档的安全。

## 隐私

- API Key 只保存在本机 `ai_config.json`，不进数据目录、不进 git。
- 开启采集后：窗口标题（进程名 + 标题）会定期发送到你在"AI设置"里配置的接口做总结；截图会上传到同一接口做描述。除此之外不会发往任何地方。
- 数据目录里是你完整的活动记录，请只放进私有仓库/私有网盘。

## 排查

- 菜单里没有"打工宠物"：多半是代码插件还没启用，见上面的安装步骤。
- 下班时宠物没动作：看 `debug.log` 最后几行，会写明当时被判定为忙碌的原因（被拖拽、工作中、旅行中等）。
- 宠物卡在放大状态：重启游戏即可复原；退出游戏时插件也会主动复原。

## 没有移植的

旧版的 OCR、中文输入（剪贴板）监听、鼠标活跃度统计、Chrome 浏览历史、聊天内容监听：价值低或不可靠，视觉描述和窗口活动已经覆盖了日报需要的信息。
